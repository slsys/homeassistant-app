# SLS

Обнаружение контроллеров SLS через LocalLink и MQTT, подключение к шлюзам,
настройка MQTT, просмотр Zigbee-устройств и диагностика внутри Home Assistant.

Поддерживаются Home Assistant OS на ARM64 (`aarch64`) и x86-64 (`amd64`).
После запуска откройте веб-интерфейс приложения и выберите контроллер в списке видимых.

Приложение использует существующую MQTT-интеграцию HA для сущностей устройств.
MQTT не требуется для самого обнаружения LocalLink.

SVG в боковом меню HA устанавливается автоматически. SLS получает доступ на запись
к конфигурации HA и право проверки и перезапуска. При первом подключении или
обновлении модуля HA один раз перезапускается. Совпадающий ранее установленный
модуль используется без перезапуска.

Доступны блоки и таблица контроллеров, фильтры и сортировка; офлайн-контроллеры всегда внизу.
Для MQTT показаны устройства Discovery, значения сущностей и переходы в HA.
Пространства и связанные объекты HA читаются через Core API (`homeassistant_api: true`).
Вкладка «Объекты HA» учитывает явные ссылки в YAML; вычисляемые динамически связи
могут быть недоступны. При неполных данных показывается уведомление.

## Подключение приложения к MQTT

По умолчанию `mqtt_mode: homeassistant`: SLS получает сообщения через MQTT-интеграцию
Home Assistant и отправляет команды через `mqtt.publish`. Брокер может находиться
на другой машине. Настройки адреса, TLS и доступа используются из интеграции HA;
повторно вводить их в SLS не требуется. Соединение обслуживается сервером приложения
и не зависит от открытой страницы браузера.

Для независимого подключения выберите `mqtt_mode: direct` в настройках приложения.
Для внешнего брокера заполните `mqtt_host`, `mqtt_port`, `mqtt_username`,
`mqtt_password`, при необходимости `mqtt_tls` и `mqtt_protocol`.
TLS проверяет сертификат по доверенным системным центрам и имени хоста.
При пустом `mqtt_host` используются реквизиты MQTT-сервиса Supervisor.
В прямом режиме диагностика локально подключённых контроллеров также может использовать
брокеры, указанные в самих контроллерах. В режиме HA такие отдельные соединения не создаются.
После изменения настроек перезапустите приложение. Автоматического переключения
между режимами нет.

`mqtt_discovery_prefix` задаёт префикс Discovery (по умолчанию `homeassistant`).
Известные префиксы контроллеров прослушиваются постоянно. Для обнаружения неизвестных
вложенных префиксов приложение при запуске и каждые `mqtt_scan_interval` секунд
(по умолчанию 300) включает подписку на все топики на 75 секунд. Между окнами
остаются узкие подписки. Новый контроллер с вложенным префиксом может появиться
после следующего окна поиска. Учётная запись брокера должна разрешать нужные топики;
подписка через HA не обходит ACL.

После перезапуска HA Core подписки восстанавливаются автоматически. Пока данные
через HA не поступают, доступность MQTT-контроллеров может быть неизвестна.
Рабочее соединение с HA само по себе не подтверждает связь с брокером.
Сохранённые сообщения не считаются новыми данными контроллера.
Перезагрузка отправляется один раз, с QoS 0 и без retain, и подтверждается
только свежими данными об аптайме. Пропущенные сообщения без сохранения
брокером не восстанавливаются.
